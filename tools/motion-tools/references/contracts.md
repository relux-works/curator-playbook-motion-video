# Draft tool provider contracts

Tools live outside the role collection (§8.5). [motion-tools](../SKILL.md) is a contract, not an executable provider. No agent-skill.json or dummy shim pretends that a renderer, contrast analyzer or provider is installed. The source kit contains CLI examples and diagnostics; it does not implement a renderer or Curator exports. HyperFrames is its intended reference renderer (kit README and component-lab.html). The unpinned npx hyperframes examples may fetch from the network; a future audited provider must pin and vendor HyperFrames, Node-compatible dependencies and local GSAP/Three.js/fonts. Never execute an unpinned fetch as a provider.

A future audited provider must export every prefixed command bound in the template; the example check-set commands now use exactly those bindings. The sets are documented proposals and are not named by a current guard, because §6.12 would pass an inline film without evidence (gap 7). The orchestrator's future Curator manifest must declare that exact provider identity in runtime mode, narrowed to those commands (§8.3, §8.5). Before publication, choose a real source/ref and validate manifests against Curator's own schema. The role collection must never directly install the tool provider as full context.

Bindings below name commands only, never shell programs or URLs. The kernel executor supplies --element and its recorded JSON input (§6.11). It runs the provider in force with sanitized environment, not a builder's PATH. Exit 0 is tool.passed; 1, errors and timeouts are failures. Any check failure carries evidence and never an invented pass. Outputs and receipts need PC3 §6.11.1; pinned checkout, resources, tier, progress and content sandbox need §6.11.2.

## Provider handoff convention (before typed outputs)

This convention is part of the proposed audited provider, not a new kernel feature. The executor supplies only the §6.11 snapshot: element id/type/fields, playbook, tool name and entry key. It does not write printed keys back to element fields before the next automatic state. In particular, analysis tools never depend on lead-transcribed scene.proof/rendered_files or deliverable.master.

The provider deployment configures a local `<artifact-dir>` accessible to its trusted adapters across invocations; this is not an inherited agent environment variable or a kernel-supplied path. Let `E=<artifact-dir>/<element-id>`. Use validated element/entry identifiers, reject path traversal and symlinks escaping E, and serialize per element. Before each chain, the lead stages a new read-only `E/inputs.json`: source paths and hashes, input generation id, expected source digest, sizes/duration, root timeline, current mix/stems, brand tokens/patches, text masks, locked dependencies/backend/seed and confirmed measurement settings. The film-specific package/source/ledger paths and beat alignment go here too. Copy approved reference/support/audio inputs here before their queued exits. Snapshot any parent inputs here explicitly; tools never silently read ancestor element fields. Missing/inconsistent inputs fail rather than reuse a previous generation. No changes to inputs.json while the chain is running.

Only trusted adapters write `E/entries/<entry-key>/<stage>/manifest.json`. Each manifest records element, entry key, input generation/digest, candidate_sha256, size/fps, provider/toolchain/tier, coverage, status and named artifact paths. Rendering/import stages atomically replace `E/active.json` with the current generation's candidate and manifest paths after success. Rendered code can write only invocation scratch; it cannot alter inputs.json, active.json, reports or measurement settings. This storage/separation must be implemented and probed by the real provider; no such adapter ships here. Its adoption with pinned invocation sandboxes remains gaps 2–3 and 9.

Later stages resolve active.json, verify its input generation, digest and size against inputs.json, then read the exact stage manifest it names. They append their own entry-keyed manifests/reports to the active candidate without changing its pixels. Music-only adds a variant/stem with its own digest and source link while preserving the primary picture candidate. Clip-prep publishes its derived clip as the new primary candidate, preserving its generation-source digest. Contact-sheets resolves difference/cut reports when present; final-size sheets can compute their own cut windows. Checks always read the decoded primary candidate plus explicitly named stems/variant. A failed run never publishes a successful manifest. Rework stages a new input generation and invalidates the old active pointer and all dependent evidence before another rendering entry. Refuse stale/wrong-generation reports even if a path exists. Kernel digest enforcement is still a proposal.

Every command prints one bounded JSON outcome (at most 16 KiB for this contract) with common keys `status`, `element_id`, `entry_key`, `input_digest`, `candidate_sha256`, `size`, `fps`, `provider_identity`, `toolchain`, `coverage`, `manifest`, `report`, `error`, plus its table keys below. Inapplicable keys are explicit nulls with a reason; large evidence lives in artifact files, never truncated stdout. These are provider outcome keys, not kernel `outputs` bindings. Exit 0 means the actual operation/check succeeded; missing evidence or an unconfigured native-frame threshold fails. The lead transcribes outcome/report paths only after the automatic chain ends in an agent-owned state, before its acceptance guards. Tool-to-tool handoff uses the manifests, never that later transcription.

## Measurement and privilege rules

- Capture from pinned local HTML/GSAP, with Three.js only where boarded. Use one root seek clock; pre-load fonts/textures. The vendor lab is a source template; work copies use local dependencies.
- Reference differences cover every decoded frame, brightness and edge detail. Sheets are timestamped and paginated with dense transitions. Scripts that output one tile or sample at 10 fps are diagnostic, not exhaustive adapters.
- Repeated-frame proof compares decoded pixels under the recorded backend. Global pure-time behaviour also needs source inspection; record the distinction.
- Measurement settings must come from the confirmed process/provider, never from scene-written files that could disable checks. Until numeric settings are adopted in §6.14, x-pc3 thresholds are specification data only.
- Contrast must include transitions and collisions. Colour compares decoded patches with tokens. Frozen runs are contiguous native-frame intervals; audio uses decoded mix and separate stems. The diagnostic threshold 0.35 applies only at 10 fps, width 320, gray YAVG of tblend difference. The native 60 fps threshold is deliberately unset; calibrate and declare it in confirmed provider settings with a rationale before a run. Do not reuse 0.35 or claim a native pass before configuration.
- Renderer content is untrusted. The future sandbox has no credentials or network and writes only invocation artifacts. Generated media and paid acquisition use a separate privileged executor with environment-variable secrets. Do not write keys into any file or expose them to agents.
- Each paid entry needs a fresh approval within its delegation ceiling and budget. Carry entry idempotency key and a receipt. Unknown charge is not free; unsupported spending is not-shipped while the owner is away.
- Reject warped clips; regenerate with a new approved paid entry. Upscale/interpolate approved geometry and label it concept. Keep the generation ledger without keys.
- Final exports must be complete at 60 fps in each requested 1080p size. Rerun checks after final encoding, including music-only and contact sheets; reject missing frame sets.
- Probes must verify the actual installed renderer, fonts, ffmpeg filters, GPU backend and providers. Package schema validation does not constitute a provider probe.

## Installed dependency references

Role skill links resolve within this source repository. Curator installs each skill as its own package, so ../business-motion-film is not guaranteed to exist in a role's installed root. Each role needs the kit in its profile; a supported content-addressed asset handle remains gap 9. No source-tree symlink is presented as a runtime solution. The orchestrator data template is a real file, so its own skill package carries it correctly.

## Final-size rework and unavailable tools

Each size runs `rendering → music-only → sheets → metrics → contrast → colour → determinism → auditing → review`. Any tool or changes_requested verdict returns to lead-owned `deliverable.rework`. The parent `film.packaging → rework` uses `children.any-in [rework]`; no invented cross-element transition changes the film. The lead clears exports_ok, invalidates all sizes (including accepted ones), repairs and re-reviews affected sections/scenes/audio and the full film, updates accepted_render_digest, and requeues the existing size elements. Every size must pass again. The single export_rework return counter and film critic_rounds counter still bound this path. Digest freshness needs gaps 1 and 7.

A refused tool entry or failing required probe lets the lead abort test-setup, reference.queued or a lead-owned queue; guarded film aborts in assembling/reporting/packaging/export-setup require tool_unavailable and an outcome. That field records actual refusal or a missing usable result after the binding timeout. Lead sessions cannot override tool-owned states. The executor reports tool.failed; an automatic kernel deadline one minute after each binding timeout is a fallback, including when the next tool entry is refused. No agent fabricates an event. Tick/executor supervision is a readiness prerequisite; a dead kernel cannot enforce any timer.

## Review isolation and deadlines

Kernel reports remain with the lead. The critic measures alone from the candidate, brief/facts and references; verification adds only the previous critic-authored report. The lead compares critic and kernel numbers afterwards in critic-round.kernel_comparison and the film ledger. Never embed kernel reports, comparisons or builder claims in the candidate packet. Every critic-owned review/verify state has an automatic $review_deadline fallback to not-shipped/unverified (default PT3H); other agent-state supervision remains gap 12. Tick/executor supervision is necessary for every deadline.
